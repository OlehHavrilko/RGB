# Roadmap

Цель: сделать Chromify максимально универсальным приложением управления
подсветкой — сначала довести до идеала контроль BLE-ленты ELK-BLEDOM,
затем научить приложение управлять ARGB-подсветкой самого компьютера
(вентиляторы, оперативная память, материнская плата) с телефона.

## Фаза 1 — довести функции BLE-ленты до идеала

- [x] Иконка приложения, инсталлятор и CI для Windows
- [x] CI-сборка Android APK
- [x] Ребрендинг RGB Control → Chromify
- [x] Экспорт/импорт пресетов (через буфер обмена, JSON)
- [x] Многодевайсность: подключение и управление несколькими BLE-лентами
      одновременно, у каждой своё состояние/таймер сна/расписание
      (`DevicesManager` держит по сессии на устройство), пресеты общие
- [x] Режим синхронизации: переключатель на экране управления — пока
      включён, изменение цвета/эффекта/яркости/питания зеркалится на все
      остальные подключённые устройства (`DevicesManager.broadcastFrom`)
- [x] Сцены: именованный снимок состояний нескольких устройств сразу — на
      разных лентах разные цвета/режимы/питание, применяется одним
      нажатием (экран «Сцены», значок в шапке «Устройства»)
- [ ] Музыкальная реакция (микрофон → цвет/яркость) — требует проверки на
      реальном железе
- [ ] Расписание на самом контроллере (если чип поддерживает) — требует
      проверки на реальном железе
- [x] Будильник-рассвет: лента плавно набирает яркость от минимума до
      целевой за заданное время вместо резкого включения (экран
      «Расписание», секция «Будильник-рассвет»)
- [x] Локализация интерфейса (RU/EN): переключатель в шапке экрана
      «Устройства», весь UI (включая имена эффектов и системные диалоги
      выбора времени) переведён на оба языка
- [x] Виджет главного экрана (Android) для быстрого вкл/выкл и пресетов:
      показывает имя/статус активного устройства, тап по индикатору питания
      или по одному из двух пресетов открывает приложение и сразу выполняет
      действие (headless BLE в фоне не проверялось на реальном железе, тап
      всегда открывает приложение)

## Фаза 2 — управление ARGB-подсветкой ПК (аналог OpenRGB)

Идея: не переизобретать протоколы производителей плат (ASUS Aura, MSI
Mystic Light, Gigabyte RGB Fusion и т.д.) — это то, что уже годами делает
сообщество OpenRGB. Вместо этого Chromify становится **клиентом** уже
запущенного на ПК OpenRGB (у него есть встроенный SDK-сервер, TCP,
порт 6742 по умолчанию).

- [x] Клиент протокола OpenRGB SDK на Dart (`lib/protocol/openrgb_protocol.dart`,
      `lib/openrgb/openrgb_client.dart`) — заголовок, `SET_CLIENT_NAME`,
      `REQUEST_CONTROLLER_COUNT`, `RGBCONTROLLER_UPDATELEDS`. **Экспериментально**:
      не проверялся против реального OpenRGB SDK Server (нет ни ПК с
      ARGB-железом, ни запущенного OpenRGB, чтобы протестировать в
      песочнице, где это писалось) — байтовый формат сверен с исходниками
      OpenRGB, но `REQUEST_CONTROLLER_DATA` (список устройств/зон/режимов)
      не реализован: количество светодиодов пока указывается вручную
- [x] Подключение по локальной сети с телефона к IP компьютера, на
      котором запущен OpenRGB SDK Server (экран «ПК», значок в шапке
      «Устройства»)
- [x] Раздел UI «ПК»: подключение по IP/порту, выбор индекса устройства и
      числа светодиодов вручную (пока не читаются с сервера), тот же
      HSV-колесо цвета, что и для BLE-ленты
- [ ] Чтение реального списка устройств/зон/режимов с сервера
      (`REQUEST_CONTROLLER_DATA`) — сейчас не реализовано, см. выше
- [ ] Единый экран со списком всех подключённых источников света
      (BLE-лента + устройства ПК) для управления из одного места
